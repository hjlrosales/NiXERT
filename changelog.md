- Completed M23 Forward-Physics Correction and Qualification Integrity by correcting the independently audited defects A1–A5 and the qualification-integrity defects B1–B4 without replacing any optimizer. A1: the layered VES kernel integrated `J0(lambda*r)/r` instead of `J0(lambda*r)`, so every layered response was mis-scaled (audit case 91.78282027 versus the independently derived image-series value 78.76163158480); the `1/r` factor is now confined to the exact homogeneous term and the correction integral uses a deterministic certified Gauss–Legendre scheme that raises `VESNumericalError` instead of returning an uncertifiable value, with the certified domain documented and the inversion search bounded by it. A2/A3: the 3D nonuniform-mesh assembly used each cell's own width twice for the higher-index neighbour (max `|A - A^T| = 1.6369`), and unequal-width faces used a harmonic mean of conductivities with an arithmetic mean of widths (`0.2666667` instead of the exact series-resistance value `0.2222222`); both 2D and 3D now share one exact two-point transmissibility, producing symmetric, conservative matrices and reciprocity to 5.8e-16. A4: imported electrode geometry is bound per source instead of from the most recent import's survey-level spacing, fails closed on mixed-source disagreement, incomplete numbering, off-line positions and topography, and carries a geometry digest into stale-result detection. A5: the unvalidated RES2DINV compatibility claim is withdrawn in favour of a documented NiX DAT dialect that rejects everything else; vendor conformance remains evidence-blocked. B1: qualification `VALIDATED` now requires an independent licence-eligible dataset, a recorded reference result, complete metrics, a convergence record and a written per-metric tolerance justification, with recursively immutable records. - Closed M23 by correcting the two remaining open code defects identified by the post-M23 independent audit. `rms_percent` overflowed to `inf` for mathematically representable percentages because the metric squares each relative residual, so an accepted finite initial model of `1e160`–`1e300` in the public 2D API (and a VES sounding whose apparent resistivities are at the `1e-190` scale in the public VES API) reported `inf` with `RuntimeWarning: overflow encountered in square` while `rms_log10` stayed finite; the quantity is now evaluated by one shared helper that keeps the conventional expression wherever it cannot overflow — so ordinary and recorded results stay bit-identical — and otherwise factors the residual magnitude out in log10 space, returning `inf` only when the exact value genuinely exceeds the double range and rejecting non-finite or non-positive input with `ValueError`. A forward-factorization failure was misclassified and mis-phased: scipy's SuperLU binding reports an exactly singular forward system as a bare `RuntimeError`, which escaped the numpy-only boundary, so `invert_ert`/`invert_ert3d` with an accepted `1e-308` initial model were recorded as `FAILED` in the `solver_update` phase although no model update was attempted; the boundary now wraps only the factorization calls of both ERT engines, converts that condition into the engine's dedicated numerical error with an explicit `forward_factorization` phase, and preserves the original cause without exposing binding-specific detail, while a `RuntimeError` from mesh/matrix assembly is still not relabelled. No optimizer, database schema, ABEM importer, or LS2 behavior changed; the external benchmark gate remains `NOT VALIDATED`, `importer_ready = false`, and M15 physical validation remains pending.
- Closed the final M23 C1 `percent_rms` defect found by the release-gate audit: scaling by the largest `log10` ratio exponent let a minute relative residual underflow the shared factor *and* the dominant term together, so `percent_rms([1e160, 1e-200], [1.0, 1e200])` raised `ValueError: math domain error` and the public `invert_ert` case (initial `1e-60` ohm-m, observations alternating between `1e-230` and `1e308`) could not report its ~`7.07e171` percentage.
